# День 6 — Агент как отдельная сущность

Ветка: `day-06` (от `improvements` — TUI на Bubble Tea v2)

## Что добавляет этот шаг

На первой неделе разговор жил **внутри экрана чата**: история сообщений,
сборка запроса, вызов API и счётчики расхода были полями модели Bubble Tea.
Второго собеседника с другими настройками завести было негде, а сравнение
моделей по `Ctrl+E` собирало запросы в обход общей логики.

Теперь всё это собрано в пакет `internal/agent`:

| тип | что делает |
|---|---|
| `agent.Config` | модель (или класс модели), system, стратегия рассуждения, сэмплирование, формат — всё, что было на первой неделе; читается из YAML |
| `agent.Agent` | владеет конфигом и историей, сам складывает стек сообщений и сам шлёт его в LLM, считает свой расход, пишет каждый вызов в журнал |
| `agent.Pool` | порождает агентов в одном процессе, ведёт общий счётчик, опрашивает группу параллельно с лимитом |
| `agent.Fleet` | описание группы агентов в YAML: общие `defaults` плюс группы с `replicas` |

Экран чата стал тонким: он правит конфиг текущего агента через панель
и показывает события его ответа. Запрос он больше не собирает.

### Поведение агента

- **Один разговор — один агент.** Второй вопрос, пока агент отвечает,
  получает `ErrBusy`: два параллельных хода перемешали бы историю.
- **История меняется только при успехе.** Неотвеченный вопрос в неё не
  попадает — после ошибки его можно просто задать заново, без отката.
- **Сброс посреди ответа выигрывает.** Ответ, начатый до `Ctrl+R`, не
  возвращает в историю то, что пользователь только что стёр.
- **Конфиг копируется, а не делится.** Температура и `stop` — указатель
  и срез; без глубокой копии правка у одного агента меняла бы её у всех.
- **Системный промпт не хранится в истории**, а подставляется при каждом
  запросе: его правка действует сразу.
- В историю попадает только вопрос и **финальный** ответ; промежуточные шаги
  стратегий дня 3 (аналитик, инженер, критик) — отдельные вызовы.
- В журнал `runs/*.jsonl` пишется **ровно тот стек, что ушёл в API**, плюс
  поле `agent` с id агента. Раньше чат собирал запрос для журнала заново
  уже после ответа, и в записанном стеке лежал ответ ассистента — то есть
  журнал показывал не то, что на самом деле ушло в API.

### В интерфейсе

| клавиша | что делает |
|---|---|
| `Ctrl+N` | новый разговор: настройки скопированы, история и лента пустые |
| `Ctrl+O` | список агентов на месте панели параметров: `↑↓` выбор, `Enter` открыть, `Ctrl+N` новый, `Ctrl+W` закрыть, `Esc` назад |
| `Ctrl+D` | что внутри текущего агента: конфиг, расход и стек, который уйдёт в API следующим запросом |

У каждого агента **своя лента на экране**: переключение возвращает
к разговору ровно в том виде, в каком его оставили. В списке разговор назван
по первому вопросу — id вроде `бюджет-003` человеку ничего не говорит.
Пока идёт ответ, переключаться и закрывать нельзя: строки ответа пишутся
в ленту текущего агента.

`Ctrl+E` (сравнение моделей) — теперь пачка агентов: пул порождает по агенту
на модель с копией текущего конфига и пустой историей, все отвечают
параллельно, потом агенты убираются. У агентов сравнения прямой ответ без
стриминга — иначе разница в таблице была бы не про модель.

### Флот: `advent swarm`

```bash
go run ./cmd/advent swarm -fleet agents/fleet.yaml
go run ./cmd/advent swarm -fleet agents/fleet.yaml -provider mock
```

Читает флот из YAML, порождает агентов в одном процессе, задаёт всем один
вопрос и печатает сводку по группам: модель, параметры, сколько ответили,
сколько верно (`expect`), средняя задержка, токены, цена. В конце — время
на стене против суммы задержек (выигрыш от параллельности) и проверка
изоляции: у каждого агента в истории ровно два сообщения.

Модель в `agents/fleet.yaml` задана **классом** (`tier: weak/strong`),
поэтому один файл работает и на DeepSeek, и на заглушке. Флот намеренно
маленький — 10 агентов в четырёх группах: на живом API прогон стоит
копейки. Масштаб задают только `replicas`; сотня агентов с разными
конфигами проверяется юнит-тестом пула на фейковом провайдере.

### Заглушка стала честнее

- **Без стриминга тоже тратит время на токены.** Раньше ответ приходил
  мгновенно, и параллельный опрос на заглушке ничего не показывал.
- **Отвечает на «как меня зовут» по присланной истории.** Заглушка, как и
  настоящая модель, не помнит прошлых запросов — видит только текущий. Если
  агент историю не передал, она честно ответит «не знаю». На репетиции
  проверяется ровно то же, что на живом API: память живёт у агента.

### Попутно исправлено

- Прокрутка переписки: флаг `follow` появился раньше, но `refresh()` его
  не читал — отлистанный вверх экран всё равно прыгал вниз на каждом куске
  ответа. Отдельный коммит.
- Запись видео находит ffmpeg вне PATH (`Resolve-Ffmpeg` в `scripts/win.ps1`).
