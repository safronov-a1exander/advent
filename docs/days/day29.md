# День 29 — локальная модель под задачу

Ветка: `day-29` (от `day-28`)

## Задача

Главный расчёт «Бюджета» — остаток бюджета по выписке (дни 3–5). Четыре
ловушки: операция чужого месяца, перевод на свой счёт, снятие наличных,
сумма в долларах. Верный ответ один — **38865**, проверка кодом
(`checks.must_contain`). Модель — Qwen3-4B в llama.cpp на RTX 4060, 8 ГБ.

В дне 26 на этом вопросе модель думала 62 секунды, выдала 4495 токенов
и ошиблась. Что можно сделать, не меняя модель:

| рычаг | где живёт | чем крутим |
|---|---|---|
| temperature, max_tokens, рассуждения | запрос | параметры варианта в сценарии |
| шаблон промпта | запрос | системный промпт варианта |
| квантовка | сервер, при загрузке модели | пресет роутера |
| окно контекста, тип KV-кэша | сервер, при загрузке модели | пресет роутера |

## Код

**Роутер llama-server с пресетами** (`scripts/llama-presets.ini`,
`scripts/local-llm.ps1 -Router`). Квантовку и окно нельзя передать
в `/chat/completions`: это настройки загрузки модели. llama-server в режиме
роутера держит их пресетами, и каждый пресет — отдельное имя модели
на одном порту:

| имя модели | веса | окно | KV-кэш |
|---|---|---|---|
| `qwen3-4b` | Q4_K_M, 2.5 ГБ | 8192 | f16 |
| `qwen3-4b-q8` | Q8_0, 4.3 ГБ | 8192 | f16 |
| `qwen3-4b-c4k` | Q4_K_M | 4096 | q8_0 |
| `qwen3-4b-c1536` | Q4_K_M | 1536 | q8_0 |

В памяти одна модель (`--models-max 1`): запрос к другой выгружает текущую.
Поэтому сравнение квантовок — обычный сценарий `lab`, как сравнение моделей
в дне 5: вариант выбирает пресет полем `model`.

**Прогрев** (`runner.Warmup`, флаг `-warmup` у `run` и `lab`). Роутер грузит
модель по первому запросу к ней, 2–3 секунды. Без прогрева они попадали бы
в задержку первого прогона каждого варианта. Перед первым вариантом на новой
модели раннер шлёт ей запрос на один токен — мимо журнала и замеров.

**`advent bench`** (`cmd/advent/day29.go`) — ресурсы, которых
из `/chat/completions` не видно. Для каждого пресета: выгрузить всё,
замерить видеопамять, загрузить, замерить снова, задать вопрос варианта
и взять `timings` самого llama-server — скорость разбора промпта
и генерации без сети и клиента. Видеопамять — разница `nvidia-smi` до
и после загрузки: по процессам Windows её не отдаёт (`N/A` в режиме WDDM).

**Шаблон промпта** (`scenarios/day29-tuning.yaml`, переменная `template`).
Маленькая модель не держит в голове пять правил и пятнадцать чисел сразу.
Шаблон раскладывает работу на шаги, каждый из которых ей по силам:

1. строка на каждую операцию — месяц, вид операции, сумма в рублях, «в счёт: да/нет»;
2. сумма только строк с «да», по одному числу, накопительным итогом;
3. бюджет минус итог.

Плюс пример на другой выписке — с теми же четырьмя ловушками, но другими
числами, чтобы модель не могла списать ответ. Месяц и курс шаблон берёт
из условия, а не знает заранее.

## Качество: до и после

`advent run -provider local -scenario scenarios/day29-tuning.yaml -warmup`,
по три прогона на вариант:

| вариант | верно | задержка | выход, ток. |
|---|---|---|---|
| до: общий промпт, параметры сервера по умолчанию | **2/3** | 21.6 с | 1450–1827 |
| только параметры: t=0, без рассуждений, max_tokens 1200 | **0/3** | 10.4 с | 804 |
| шаблон под задачу | **3/3** | 11.1 с | 827–836 |
| шаблон + окно 4096, KV-кэш q8_0 | 3/3 | 11.4 с | 836 |
| шаблон + Q8_0 | 3/3 | 16.6 с | 836 |
| шаблон + окно 1536 | 0/3 | 4.9 с | 362, `length` |

**«До».** Qwen3 по умолчанию рассуждает, `temperature` сервера 0.8,
`max_tokens` нет. Два прогона верны, третий — 32295. Рассуждения помогают,
но это лотерея: в дне 26 тот же вопрос дал 41875.

**Только параметры.** Очевидный ход ради скорости — выключить рассуждения
и зафиксировать температуру. Вдвое быстрее и стабильно: все три прогона
слово в слово. И все три неверны (23125): без рассуждений модель
складывает всё подряд, правила теряются. Стабильность не равна точности.

**Шаблон.** Те же параметры, другой промпт — три из трёх. Рассуждение
никуда не делось, оно в ответе, но в жёсткой форме: решение по каждой
строке видно, его можно проверить глазами. Вдвое быстрее «до» и вдвое
меньше токенов.

Первая версия шаблона ошиблась ровно в одном месте: посчитала 10 USD как
90 рублей. Помогло вынести умножение в отдельный шаг строки —
`10 USD × 90 = 900`. Маленькой модели нужно записать промежуточное число,
держать его «в уме» она не умеет.

**Квантовка.** Q8_0 отвечает так же верно, но в полтора раза медленнее.
Шаблон уже снял ошибки, и точнее веса ничего не добавили.

**Окно.** Задаче нужно ~2000 токенов: промпт 1174 и ответ ~830. Окно 4096
отвечает тем же, а окно 1536 обрывает ответ на 362-м токене, до строки
`ОТВЕТ` (`finish_reason: length`). Экономить окно можно, пока в него
влезают промпт и ответ вместе. (Окно 2048 проходит впритык: 1172 + 827 = 1999.)

## Ресурсы

`advent bench -provider local -scenario scenarios/day29-tuning.yaml -variant template`,
видеокарта свободна от других моделей:

| пресет | загрузка | видеопамять | разбор промпта | генерация |
|---|---|---|---|---|
| Q4_K_M, окно 8192 | 2.2 с | 3721 МБ | 3723 ток/с | 75.8 ток/с |
| Q4_K_M, окно 4096, KV q8_0 | 2.2 с | **2873 МБ** | 3586 ток/с | 74.5 ток/с |
| Q8_0, окно 8192 | 2.8 с | 5422 МБ | 3943 ток/с | **50.8 ток/с** |

- **Окно и KV-кэш** — минус 850 МБ (23%) при той же скорости и том же
  ответе. KV-кэш растёт с окном, а не с длиной разговора: llama.cpp
  выделяет его целиком при загрузке.
- **Q8_0** тяжелее на 1.7 ГБ и генерирует в полтора раза медленнее:
  генерация упирается в пропускную способность памяти, а весов больше.
- **Соседи по видеокарте.** Тот же замер рядом с эмбеддингами
  и реранкером дня 28 (ещё ~1.2 ГБ): Q8_0 занял 5096 МБ вместо 5422 —
  часть весов драйвер вынес в общую память. Разбор промпта упал до 466 ток/с
  (в 8 раз), генерация — до 43 ток/с. Q4_K_M рядом с ними работает
  без потерь. На 8 ГБ Q8 и база знаний вместе не помещаются.

## Итог: конфигурация под задачу

| | до | после |
|---|---|---|
| промпт | общий | шаблон: строка на операцию, сумма по шагам, пример |
| рассуждения | включены | выключены — шаг рассуждения в шаблоне |
| temperature | 0.8 (сервер) | 0 |
| max_tokens | нет | 1200 — потолок на случай, если модель зациклится |
| квантовка | Q4_K_M | Q4_K_M — Q8 не точнее, но медленнее |
| окно | 8192, KV f16 | 4096, KV q8_0 |
| верно | 2/3 | 3/3 |
| задержка | 21.6 с | 11.4 с |
| видеопамять | 3721 МБ | 2873 МБ |

Главный рычаг — промпт, а не параметры и не квантовка: параметры дали
скорость ценой точности, квантовка — точность, которая уже была. Шаблон
вернул точность и сохранил скорость.

## Запись демо

Видеокарта нужна свободной: серверы базы знаний останавливаются, чат-модель
поднимается роутером. После записи — обратно, для дня 28.

```powershell
$env:LLAMA_CPP_DIR = 'C:\Users\sanya\tools\llama'   # если не $HOME\tools\llama
.\scripts\rag-servers.ps1 -Stop
.\scripts\local-llm.ps1 -Router -Restart
$t = 'advent · день 29 — локальная модель под задачу'
.\scripts\demo.ps1 -Name day29 -MaxSeconds 1500 -AppArgsList @(
  @('lab','-provider','local','-scenario','scenarios/day29-tuning.yaml','-warmup','-script','scripts/day29.demo'),
  @('bench','-provider','local','-scenario','scenarios/day29-tuning.yaml','-variant','template','-models','qwen3-4b,qwen3-4b-c4k,qwen3-4b-q8','-hold','25s'))
```
