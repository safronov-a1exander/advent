# День 31 — ассистент разработчика

Ветка: `day-31` (от `day-30`)

## Что добавляет этот шаг

Задание — ассистент, который понимает проект: RAG по документации,
MCP к репозиторию, команда `/help`. Автор курса сформулировал это
короче: «RAG для документации, MCP для гита, ядро — агент». Агент,
поиск с реранком и цитатами, цикл инструментов MCP уже есть. Новое —
собрать их под один проект: сам стенд.

```
advent dev ──► агент ──► /help: поиск по index/project ──► фрагменты ┐
                 │                                                   ├─► deepseek-flash
                 └──► MCP git: branch · status · files · diff · log ─┘
```

| требование | где сделано |
|---|---|
| README + docs в RAG | база `project` в `rag.bases`: README, ранбук, `ARCHITECTURE.md`, заметки всех дней |
| схемы данных / API | там же: `config.yaml` (схема конфига), `cmd/advent/main.go` (команды), `internal/servers/**` (схемы MCP-инструментов) |
| MCP — хотя бы git branch | свой сервер `git` (`internal/servers/gitrepo`): `branch`, `status`, `files`, `diff`, `log` |
| `/help` отвечает о проекте | `advent dev`, команда `/help <вопрос>` |

### Отдельные базы знаний

До сих пор база знаний была одна, и в неё нарочно не входили заметки
дней 21+: там контрольные вопросы с ответами. Ассистенту разработчика
нужна другая база, с заметками всех дней. Поэтому в конфиге появился
раздел `rag.bases`: у каждой базы свои источники и свой каталог индекса
`index/<база>/`. Нарезка и модели общие.

```powershell
.\advent.exe index -base project -strategy structure
.\advent.exe search -base project -rerank "какие инструменты у сервера budget"
.\advent.exe chat -kb project -rag-chat          # та же база в обычном чате
```

### `/help` и обычная реплика — разные ходы

- **`/help <вопрос>`** — поиск по базе проекта (реранк, rewrite, цитаты
  с проверкой, раздел целиком — всё из дней 23–25) плюс состояние
  репозитория. Ветку, последний коммит и число незакоммиченных файлов
  код берёт у сервера git **до вопроса**, тем же вызовом инструмента,
  что доступен модели, и кладёт в системный промпт этого хода. Ответ
  «на какой мы ветке» не должен зависеть от того, догадается ли модель
  вызвать инструмент.
- **`/help`** без вопроса — ветка и коммит, без модели.
- **обычная реплика** — разговор без поиска; инструменты git модель
  вызывает сама, если нужно.

Сервер git только читает. Коммит, push и смена ветки — опасные операции
из лекции недели. Ассистенту, который отвечает на вопросы, они не нужны.
Имя ветки из аргументов модели проверяется: строка, начинающаяся с `-`,
стала бы флагом git, и через `base=--output=…` можно было бы записать файл.

## Что вскрыла связка

### 1. «Не знаю» там, где ответит git

Первый прогон ответил «не знаю» на два вопроса из трёх. На вопрос
«что сделано на ветке» в документации ответа нет и быть не может.
А режим цитат дня 24 при пустом поиске отказывает **кодом, до модели**,
поэтому до инструментов git дело не доходило.

Для ассистента разработчика пустой поиск — не отказ. Новое поле агента
`rag_open`: если ничего не прошло порог, вопрос уходит модели без
фрагментов и без режима цитат, с пометкой «в документации ничего не
нашлось, отвечай по инструментам». Ответ подписан честно:
«Источник: в документации не нашлось — ответ по инструментам и разговору».
На прогоне модель сама вызвала `git.diff {base: day-30, stat: true}`,
`git.log {base: day-30}` и `git.status` и перечислила изменённые файлы.

### 2. Дерево каталогов не ищется

«Как устроен проект: какие каталоги и за что отвечают» — тоже «не знаю»,
хотя в README есть раздел «Структура». Но это дерево путей в блоке кода:
по косинусу этот кусок оказался **37-м**, до реранка не дошёл, а лучшие
кандидаты реранкер оценил в 0.00. Эмбеддингу не за что зацепиться
в списке `internal/agent/   агент…`.

Чинится не поиском, а документом: `docs/ARCHITECTURE.md` — та же карта
словами: путь запроса, за что отвечает каждый каталог. Тот же вопрос
находит её первой с оценкой реранкера 0.94.

### 3. Цитаты выталкивают ответ

На обзорный вопрос модель приносит по цитате на каждый пункт: 14 строк
цитат вытолкнули сам ответ за верх экрана. Теперь под ответом видны все
непроверенные цитаты и только первые четыре дословные. Остальные —
строкой «… и ещё N — тоже дословно», а итог проверки по-прежнему
считает все.

### 4. Таблица README отстаёт

Ассистент ищет по README, а таблица шагов в нём кончается на дне 25.
Это не ошибка поиска, а устаревшая документация. Её обновление —
сценарий для ассистента по файлам проекта (день 34).
