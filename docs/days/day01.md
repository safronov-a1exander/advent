# День 1 — Первый запрос к LLM через API

Ветка: `day-01` (от `main`)

## Сквозной проект

Все шаги собираются в один продукт — **«Бюджет», ассистент по личным
тратам**. Домен один, меняется только то, что добавляет очередной шаг:

| шаг | что делает ассистент |
|---|---|
| 1 | отвечает на вопрос про траты прозой |
| 2 | достаёт из банковской выписки структуру (JSON) |
| 3 | считает остаток бюджета — четырьмя способами рассуждения |
| 4 | тот же расчёт при разных температурах + генерация идей по экономии |
| 5 | тот же расчёт на слабой, средней и сильной модели |

Дальше на этот же домен ложатся память о лимитах и категориях, RAG по
истории трат, агент с инструментами и деплой бота.

## Что добавляет этот шаг

Минимальный путь — команда `ask`: собирает `messages`, шлёт
`POST /chat/completions`, печатает ответ. Всё, что нужно для первого шага.

Поверх — TUI (`chat`) с **панелью параметров справа**: модель, системный
промпт и стриминг правятся прямо на экране, без перезапуска с флагами.
Каждый следующий день дописывает в эту панель свои параметры, и на ветке
дня N доступны все параметры дней 1…N.

Внизу — **блокнот**: отдельная панель, куда можно печатать руками и куда
демо-сценарий набирает комментарии посимвольно. Сделано ради видео: в самой
переписке остаётся только разговор с ассистентом, без подписей «смотрите
сюда». Заголовок окна — имя продукта.

Клавиши: `Tab` водит по кругу ввод → параметры → блокнот, `Esc` возвращает
в диалог из любого места, `↑↓` — поле панели, `←→` — значение,
`Enter` — ввести значение руками, `Ctrl+P` — спрятать панель,
`Ctrl+R` — сбросить контекст, `Ctrl+L` — очистить экран.

Системный промпт хранится не в истории, а подставляется в каждый запрос
заново — поэтому его правка действует сразу, а не после сброса контекста.

Ключевые файлы:

| файл | что там |
|---|---|
| `internal/llm/openai_compat.go` | сам HTTP-вызов, разбор ответа и SSE-потока |
| `internal/llm/types.go` | Request/Response/Usage — общий контракт |
| `internal/config/config.go` | провайдеры, ключ из env, прайс |
| `internal/store/store.go` | журнал каждого вызова в `runs/*.jsonl` |
| `internal/tui/chat.go` | экран чата |
| `internal/tui/field.go` | виджет панели параметров (общий для всех дней) |
| `internal/tui/settings.go` | параметры запроса, редактируемые на лету |
| `cmd/advent/day01.go` | команды `ask`, `chat`, `demo` |

## На что смотреть при прогоне

1. Положить ключ: `setx DEEPSEEK_API_KEY "sk-..."` (перезапустить терминал)
   либо создать `config.local.yaml` с `api_key`.
2. Проверить связь:
   ```bash
   go run ./cmd/advent doctor
   ```
   Должно напечатать «стенд готов» и количество доступных моделей.
3. Сверить список моделей с реальностью и, если имена отличаются от
   `deepseek-v4-flash` / `deepseek-v4-pro`, поправить `config.yaml`:
   ```bash
   go run ./cmd/advent models
   ```
   Там же лежат цены — они **плейсхолдеры**, подставь реальные с
   api-docs.deepseek.com, иначе колонка стоимости везде будет врать.
4. Прогнать разок вживую, чтобы понимать, что показываешь:
   ```bash
   go run ./cmd/advent ask "За выходные потратил: супермаркет 2340, кофейня 390, такси 620. Сколько всего?"
   ```
