# День 2 — Формат ответа

Ветка: `day-02` (от `day-01`)

## Что добавляет этот шаг

Появился движок экспериментов. Один запрос описывается в YAML, варианты
отличаются только параметрами, а ответ проверяется автоматически — чтобы
в видео был объективный вердикт, а не «мне кажется, формат соблюдён».

| файл | что там |
|---|---|
| `scenarios/day02-format.yaml` | сам эксперимент: 5 вариантов одного запроса |
| `data/statement.txt` | банковская выписка — общие данные для дней 2–5 |
| `internal/scenario/` | разбор YAML, слияние параметров, шаблоны `{{.task}}` |
| `internal/runner/` | прогон вариантов + проверки ответа |
| `internal/report/` | таблица в консоль и markdown-отчёт в `reports/` |
| `internal/tui/lab.go` | экран сравнения: варианты, ответ с проверками, панель параметров |
| `cmd/advent/day02.go` | команды `run` и `lab` |

Шаг сквозного проекта: ассистент по тратам учится превращать сырые строки
выписки в структуру, с которой дальше можно считать бюджет. Выписка лежит
в `data/statement.txt` и подключается через новое поле `vars_files` —
одни и те же данные во всех днях, без копипасты.

Пять вариантов — по нарастающей:

1. без ограничений — базовая линия, ответ прозой;
2. формат описан словами — обычно работает, но обёртка в ` ```json ` ломает разбор;
3. `+ max_tokens: 150` — двенадцать операций не влезают, ответ обрубает
   на лимите, `finish_reason` становится `length`, JSON битый;
4. `+ stop: ["<<<END>>>"]` — промпт ставит маркер, параметр обрывает генерацию
   ровно на нём;
5. `+ response_format: json_object` — формат гарантирован параметром API.

Проверки: валидный JSON → массив `transactions` → у каждого элемента поля
`merchant`/`amount`/`category` → нет ` ``` ` → `finish_reason == stop`.

Панель параметров справа работает **слоем поверх сценария**: пустое поле
означает «как в YAML», заполненное — навязывает значение всем вариантам
сразу. Прямо в видео можно выкрутить `max_tokens` в 40 и показать, что на
таком лимите не выживает даже `response_format` — JSON не успевает
закрыться. Появились поля `max_tokens`, `stop`, `response_format`
и число повторов; параметры дня 1 (модель, system) остаются на месте.

## Проверено на живом API

Два подводных камня DeepSeek, оба вылезли на первом же настоящем прогоне:

- **Рассуждения съедают `max_tokens`.** С включённым reasoning вариант 4
  упирался в лимит: 1200 из 1200 completion-токенов ушли в рассуждения,
  до JSON генерация не дошла, `finish_reason: length`. В сценарии стоит
  `thinking: disabled` — день про формат, а не про режим инференса.
- **`response_format: json_object` требует слово «JSON» в промпте.** Иначе
  API отвечает `400 Prompt must contain the word 'json' in some form to use
  'response_format' of type 'json_object'`.

Прогон целиком: 5 вызовов, ~13 секунд, **$0.0033** по пиковому прайсу.

## На что смотреть при прогоне

1. Прогнать вживую и посмотреть, что получилось (ожидаемо: 1 и 3 красные,
   2, 4 и 5 зелёные):
   ```bash
   go run ./cmd/advent run -scenario scenarios/day02-format.yaml -full
   ```
2. Проверить, что вариант 3 действительно упал в `finish_reason: length`.
   Если DeepSeek уложился в 150 токенов — уменьшить `max_tokens` в YAML,
   иначе на видео не будет видно смысла ограничения.
3. Проверить, что вариант 2 хотя бы иногда обёртывает ответ в ` ```json `.
   Если модель ведёт себя идеально, это тоже нормальный результат — тогда
   в видео скажи, что prompt-only формат сработал, но гарантий не даёт.
4. Отчёт лежит в `reports/day02-format-<дата>.md` — его можно приложить
   к результатам прогона.
