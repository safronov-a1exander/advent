# День 18 — планировщик и фоновые задачи

Ветка: `day-18` (от `day-17`)

## Что добавляет этот шаг

Агент, который сам присылает сводку по расписанию. Ведущий курса
сформулировал смысл дня одной фразой: «сделать агента, который тебе
присылает сводку раз в какое-то время», — и сразу предупредил о главном:
«у агента нет такого понятия как heartbeat», любые команды вроде
«присылай каждый час» «будут игнорироваться и слетать».

Поэтому расписание живёт **снаружи агента**, в двух местах:

```
  сервер «Курсы» (отдельный процесс, HTTP)          advent watch (таймер)
  ┌─────────────────────────────────────┐         ┌──────────────────────┐
  │ планировщик: каждые 5 с проверяет   │         │ каждые N минут:      │
  │ сроки заданий → замер курса рынка   │◄─ MCP ──│ новый агент          │
  │ → runs/mcp/rates-watch.json         │         │ «собери сводку»      │
  │ инструменты: watch_rate, rate_digest│         │ → runs/digests.md    │
  └─────────────────────────────────────┘         └──────────────────────┘
```

- **Сервер копит данные сам.** Инструмент `watch_rate` заводит задание,
  а замеры делает планировщик сервера — когда к серверу никто не подключён.
- **Таймер будит агента.** `advent watch` раз в период создаёт агента
  и задаёт ему один и тот же вопрос; агент сам решает, какие инструменты
  позвать, и пишет сводку.

## Сервер: инструменты с отложенным выполнением

К двум инструментам дня 17 добавились четыре:

| инструмент | что делает |
|---|---|
| `watch_rate(currency*, every*)` | завести слежение за валютой с периодом `30s`, `5m`, `1h`; повторный вызов меняет период |
| `unwatch_rate(currency*)` | снять слежение вместе с историей |
| `list_watches()` | что отслеживается, сколько замеров, последний курс, ошибки |
| `rate_digest(currency*, window)` | агрегат за окно: было/стало, изменение в %, минимум и максимум со временем, среднее, пропуски |

Задание требует, чтобы инструмент «сохранял данные, выполнялся по
расписанию и возвращал агрегированный результат», — это ровно
`watch_rate` → планировщик → `rate_digest`.

### Откуда курс

Курс ЦБ публикуется раз в день, и замерять его каждую минуту
бессмысленно. Для слежения нужен курс рынка — его отдаёт публичный API
Coinbase: таблица курсов к доллару для фиатных валют и криптовалют,
рубль за единицу считается кросс-курсом. Один запрос на все валюты.

Честная оговорка: валютный рынок в выходные закрыт, и доллар с евро
в субботу и воскресенье стоят на месте. Биткоин торгуется круглосуточно.
Сводка это покажет как есть: «изменение +0.000%» — тоже результат.

### Почему сервер отдельным процессом

На семнадцатом дне сервер жил подпроцессом чата: закрыли чат — закрылся
stdin — сервер ушёл. Серверу с расписанием так нельзя, поэтому у него
появился второй транспорт — **Streamable HTTP**:

```bash
go run ./cmd/advent mcp-server rates -http 127.0.0.1:8765
```

Клиенты приходят и уходят, а планировщик работает, пока жив процесс.
Сервер отвечает обычным JSON (SSE ему не нужен: он не шлёт уведомлений
посреди вызова), выдаёт сессию на `initialize` и отвечает 404 на
незнакомую — сигнал клиенту начать заново.

Клиентская сторона научилась это переживать: если сервер перезапустился,
пока агент жил, хаб ловит «сессия больше не действует», делает новое
рукопожатие и повторяет вызов. Для долгоживущего агента это не редкость,
а обычный вторник.

### Переживает перезапуск — и не врёт про пропуски

- Задания и замеры лежат в JSON (`-data`), запись атомарная: временный
  файл и переименование. Упади процесс посреди записи — останется
  прежний файл, а не половина JSON.
- После простоя сервер делает **один** замер, а не «догоняет» пропущенные
  пачкой: прошлого курса рынка у нас нет, и десять замеров подряд были бы
  одним и тем же числом с разными метками времени.
- Пропуск виден в сводке: «Пропусков в замерах: 1 — сервер не работал
  или рынок не отвечал». Дыра в данных — это данные.
- Замер, который не удался, не ломает задание: счётчик ошибок подряд
  и последняя ошибка видны в `list_watches`.
- Не чаще раза в 10 секунд: чужой API — не наш, а курс за десять секунд
  почти не меняется. Истории — до 10 000 замеров на валюту.

## Агент: `advent watch`

```bash
go run ./cmd/advent watch -every 5m              # работать, пока не остановят
go run ./cmd/advent watch -once                  # одна сводка и выход — для cron
```

Каждый раз — **новый агент с чистой историей**. Сводке не нужны прошлые
сводки, а тащить их с собой — платить за них в каждом следующем запросе
(день 8). Всё, что нужно помнить между сводками, помнит сервер.

Сводка печатается и дописывается в `runs/digests.md` — это и есть
«присылает»: файл, который можно открыть, переслать или отдать дальше.

### Настоящий cron

Встроенный таймер — для демо и для запуска «в терминале на ночь».
Для 24/7 его заменяет планировщик ОС, а `-once` делает одну сводку:

```bash
# Linux / VPS: сводка в начале каждого часа
0 * * * * cd /opt/advent && ./advent watch -once >> runs/watch.log 2>&1
```

```powershell
# Windows, Планировщик задач
schtasks /create /tn advent-digest /sc hourly /tr "C:\dev\advent\bin\advent.exe watch -once -dir C:\dev\advent"
```

Сервер слежения при этом запускается один раз и живёт сам — службой,
`systemd`-юнитом или просто в `tmux` на VPS.

## Проверено

Тестами: расписание (срок не подошёл — замера нет), перезапуск из файла,
один замер после простоя вместо десяти, пропуск в сводке, окно сводки,
слишком частый период и неизвестная валюта, сервер по HTTP с перезапуском
на том же адресе — хаб сам делает новое рукопожатие.

На заглушке (`-provider mock`, рынок `-market walk`): чат завёл слежение
за тремя валютами, сервер сам делал замеры, `advent watch` по таймеру
позвал `list_watches` и `rate_digest` по каждой валюте и дописал сводки
в файл.

### Живой API

`deepseek-flash`, рынок Coinbase, воскресенье 27.09.2026. Чат завёл
слежение за USD, EUR и BTC, `advent watch -every 1m` сделал три сводки
подряд, каждая — новый агент:

| сводка | вызовов API | инструменты | вход | выход | $ |
|---|---:|---|---:|---:|---:|
| 08:05:27 | 3 | `list_watches` → `rate_digest` ×3 | 4 215 | 351 | 0.000305 |
| 08:06:32 | 3 | `list_watches` → `rate_digest` ×3 | 4 215 | 350 | 0.000304 |
| 08:07:36 | 3 | `list_watches` → `rate_digest` ×3 | 4 215 | 361 | 0.000317 |

Что видно:

- **Каждая сводка стоит одинаково.** Вход 4 215 токенов три раза подряд:
  агент каждый раз новый, история не растёт, а растущие замеры живут
  на сервере и приходят агрегатом. Сутки сводок раз в час — меньше цента.
- **Маршрут модель строит сама и каждый раз одинаково:** сначала
  `list_watches` — узнать, за чем следим, — потом `rate_digest` по каждой
  валюте тремя параллельными вызовами в одном круге. Поэтому вызовов API
  три, а не пять: два круга с инструментами и ответ.
- **Выходные видно по цифрам.** Доллар и евро все три сводки стоят
  на месте — валютный рынок закрыт. Биткоин двигается: −0.027%, −0.018%,
  +0.008%. Модель сама назвала это шумом, а не трендом.

### Модель придумала ограничение, о котором ей не сказали

В первом дубле пользователь попросил «каждые 20 секунд», а модель завела
слежение с периодом `30s` и объяснила: «минимально возможный, 20 секунд
не поддерживается». Сервер пускает от 10 секунд — но нигде этого не
говорил, а в описании аргумента стоял пример «30s, 5m, 1h». Модель
приняла первый пример за нижнюю границу и сочинила причину.

Исправление — одна строка схемы: «10s, 20s, 5m, 1h; не чаще раза в 10s».
Со вторым дублем модель ставит ровно `20s`. Вывод дня 17 с другой
стороны: описание инструмента — это промпт, и если в нём нет правила,
модель додумает его сама — уверенно и с объяснением.
