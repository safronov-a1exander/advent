# День 35 — реальная задача: сдача дня челленджа

Ветка: `day-35` (от `day-34`)

## Какую задачу решаю

Каждый из тридцати пяти дней этого репозитория кончается одной и той же
рутиной:

1. ветка `day-NN` ответвлена от `day-(NN-1)`, всё закоммичено;
2. `gofmt`, `go vet`, `go test` проходят;
3. есть заметка `docs/days/dayNN.md` со строкой «Ветка: … (от …)»;
4. в README есть строка дня в таблице шагов и звено в цепочке веток;
5. есть демо-сценарий и видео — не битое;
6. ветка запушена, открыт PR «Day NN — тема» с описанием;
7. в таблицу сдачи уходят ссылки на ветку и видео.

Руками это делалось каждый раз немного по-разному и с потерями. Их видно
по истории: таблица README отстала на девять дней (дни 26–34 вписал
ассистент дня 34). Видео дня 31 «записалось» без единого кадра: ffmpeg
без libx264 упал сразу, а прогон шёл впустую. Описание каждого PR
писалось с нуля. Это не учебный пример, а задача, которую я решаю каждый
день.

## Как участвует AI

`advent ship` — пайплайн по лекции недели. Проверки — кодом, суждения —
субагентам, публикация — человеку.

```
advent ship
  │
  ├─ 1. цепочка проверок кодом ─ ветка · дерево · gofmt · vet · test · заметка
  │                              · README · демо · видео (ffprobe) · push · PR
  │      ✗ без исправителя (тесты, видео…) ─► стоп: «сдавать нельзя»
  │
  ├─ 2. субагенты веером, параллельно, у каждого свой контекст:
  │      • ревьюер — пайплайн дня 32 на работе ветки (RAG по правилам и коду)
  │      • автор PR — заголовок, описание в стиле прошлых PR, тезисы для видео
  │      • редактор README — ассистент дня 34; роутер зовёт его,
  │        только если проверка README провалена
  │
  └─ 3. план публикации: git push · gh pr create (в main или стеком)
         └─ выполнить? [y/N] ─ человек; -yes — разрешил заранее; -dry — только план
```

| паттерн лекции | где |
|---|---|
| субагенты, у каждого своя задача и своё окно | `ship.Subagent`: ревьюер, автор PR, редактор README — свои промпты и свои агенты |
| fan-out | `ship.FanOut`: выбранные субагенты идут параллельно, упавший не роняет остальных |
| цепочка | проверки по порядку, дальше — только если нет блокирующих провалов |
| роутер | `When: NeedsFix("редактор README")` — субагент запускается по итогам проверок |
| человек в цепи | push и PR — только после «y», `-yes` или из рук человека; `request_changes` ревьюера — предупреждение, решает человек |
| error handling | у ревьюера — повторы и запасной путь дня 32; «автор PR» не справился — PR не предлагается, остальное идёт |
| метрики | время и цена каждого субагента — в логе и в отчёте |

Жизненный цикл субагента — как в лекции: создан, исполнен, вернул
результат, умер. Каждый живёт одну функцию `Run`, со своим пулом
и своим контекстом. Ревьюер не видит описания PR, автор PR не видит diff
целиком — только заметку, историю коммитов и список файлов.

## Работает в реальном окружении

Записанный прогон — сдача настоящего дня 34 (`git checkout day-34`,
`advent ship -dry`):

- 11 проверок за 6 секунд: 9 ✓, ⚠ «демо-сценария нет» (демо дня 34 —
  консольные команды) и ⚠ «PR ещё нет»;
- роутер: README в порядке — редактор не нужен;
- автор PR — 3.2 с, $0.0005: заголовок «Day 34 — ассистент по файлам
  проекта», описание в стиле прошлых PR, три тезиса для видео — про лимит
  кругов, цену по пулу и проверку «по памяти»;
- ревьюер — 14.5 с, $0.0024: `request_changes`, 7 багов (1 high);
- план: `gh pr create --base day-33 --head day-34 …`. Base — `day-33`:
  `day-33` ещё не влит в `main`, поэтому PR стековый, чтобы в diff был
  только этот шаг. Без подтверждения ничего не выполнено, отчёт —
  в `reports/ship/day34.md` вместе с текстом для таблицы сдачи.

## Что не полностью рабочее и почему

- **Таблица сдачи** — Google Sheets курса. Ключей к ней у стенда нет,
  и заводить их ради одной строки незачем. `ship` готовит текст
  комментария: ссылку на ветку и путь к видео, которое нужно загрузить.
- **Загрузка видео** — руками: облачный диск курса работает «кластерами»
  (сбои Яндекса в чате курса), автоматизировать загрузку туда — значит
  отлаживать чужой сбой.
- **VPS нет** — всё работает на этой машине, как и вся неделя.

## Что вскрылось

### Ревьюер — материал для решения, а не решение

На двух прогонах по дню 34 ревьюер оба раза поставил `request_changes`.
По фактам:

| замечание | правда? |
|---|---|
| 🔴 песочница путей не проверяет выход за корень через `-stage` | переоценено: в тексте замечания модель сама пишет «не критично» и «ок» |
| `NUL` вместо `/dev/null` на Windows — diff нового файла не сработает | нет: проверено, `git diff --no-index` с `NUL` даёт `--- /dev/null` и `new file mode` |
| логика `existed` в `write_file` инвертирована | нет: `existed == nil` — файл есть, «перезаписан» |
| результат `Clean` в `applyStage` игнорируется | нет: ошибка возвращается |
| в заметке упомянут `scripts/day34.demo` | нет такого упоминания |
| ошибки `filepath.Abs` и записи diff не проверяются | да, мелочь |

Поэтому вердикт ревьюера в `ship` — предупреждение «посмотри отчёт,
прежде чем подтверждать», а не блокировка. Блокируют только проверки
кодом, которые нельзя оспорить: тесты, формат, заметка, видео.

### Сдача самого дня 35

Последним `advent ship -dry` прогнал этот же день. Проверка README
провалилась — строки дня 35 нет, — и роутер впервые запустил третьего
субагента. Редактор README (ассистент дня 34) за 12 с и $0.005 дописал
звено цепочки и строку таблицы в черновик. Человек посмотрел
`advent files -diff`, применил и закоммитил. Все три субагента шли
параллельно, общее время — 12 с, по самому медленному.

На этот раз ревьюер попал. `git push` выполнялся из текущего каталога,
а не из корня репозитория, и с `-dir` ушёл бы не туда. Ошибка `fetch`
глоталась, и без сети PR молча открылся бы стеком вместо `main`. Ответ
`gh` и `os.Stat` видео не проверялись. Всё исправлено до публикации —
ради этого ревьюер в цепочке и стоит.

### Видео проверяет ffprobe, а не наличие файла

Файл записи есть всегда: `demo.ps1` создаёт его до старта ffmpeg. Битая
запись дня 31 весила бы сотню байт. Проверка смотрит размер и длительность
по ffprobe, а ffprobe ищет так же, как `scripts/win.ps1`: в PATH или
в каталоге OBS, где версия в пути меняется.

## Запуск

```powershell
.\advent.exe ship              # на ветке day-NN: проверки, субагенты, план, вопрос
.\advent.exe ship -dry         # только план, без вопроса
.\advent.exe ship -yes         # публикация без вопроса — человек разрешил заранее
.\advent.exe ship -day 34 -skip-tests
```

## Запись демо

Видео — сдача дня 34: бинарь собран с ветки `day-35`, запуск на `day-34`.

```powershell
git checkout day-34
.\scripts\demo.ps1 -Name day35 -SkipBuild -MaxSeconds 900 -AppArgsList @(@('ship','-dry','-hold','35s'))
```
