# День 11 — модель памяти агента

Ветка: `day-11` (от `day-10`)

## Что добавляет этот шаг

На девятом дне разошлись **память** (вся история разговора) и **контекст**
(что из неё уходит в модель). Но памятью там была история одного разговора,
а она умирает вместе с ним: закрыл чат — и агент снова не знает ни кто ты,
ни чем вы заняты.

Одиннадцатый день разбирает саму память на три слоя с разным временем жизни.

| слой | что хранит | живёт | где лежит |
|---|---|---|---|
| `chat` — краткосрочная | текущий диалог: история и заметки «на сейчас» | до `Ctrl+R` | в файле разговора |
| `task` — рабочая | данные задачи: цель, требования, решения | дольше разговора | `memory/tasks/<задача>.json` |
| `user` — долговременная | профиль, предпочтения, знания о собеседнике | дольше задачи | `memory/users/<юзер>.json` |

Слои **ортогональны стратегиям контекста** дней 9–10. Стратегия решает, как
ужать историю — то есть только краткосрочный слой. Рабочий и долговременный
уходят в системный промпт отдельными блоками и ужатию не подлежат: они
и так короткие, а сжимать их значит терять ровно то, ради чего они заведены.
Поэтому `-context window -memory auto` — рабочая комбинация: модель почти не
видит переписки, но задачу помнит.

### Кто раскладывает

Задание требует «явно выбирать, что и куда сохраняется». Это два разных
способа, и нужны оба.

- **Руками** (`memory: manual`) — прямо из поля ввода:
  `/user стек = Go`, `/task срок = 6 недель`, `/chat остановились = на оплате`,
  `/forget task срок`. Надёжно, ничего не стоит, но человек половину забудет.
- **Служебным вызовом** (`memory: auto`) — после каждой реплики пользователя
  отдельный вызов раскладывает новое по слоям. Ничего не забудет, но ошибётся;
  в ленте видно, что он решил, а в панели — что положил агент, а что вы.

Раскладка возвращает **только разницу**, а не весь набор:

```json
{"remember": [{"scope": "user", "key": "имя", "value": "Олег"}], "forget": []}
```

Это прямой вывод из дня 10. Факты каждый ход переписывали весь блок целиком,
и это вышло дорого: выход вдвое больше остальных вариантов, а меняющийся
системный промпт убивал кэш префикса (85% → 1%). Разница решает обе беды
сразу — обычная реплика даёт `{"remember": [], "forget": []}` и почти нулевой
выход, а блоки слоёв между ходами не меняются, и префикс остаётся прежним.

### Что где не хранится

- Краткосрочный слой **не** лежит в каталоге памяти: он принадлежит разговору
  и уезжает на диск вместе с ним, в тот же файл сессии дня 7.
- Рабочий и долговременный **не** лежат в файле разговора: у одной задачи
  разговоров бывает много, и каждый хранил бы свою расходящуюся копию.
- `Ctrl+R` стирает историю и краткосрочный слой. Задача от этого не кончилась,
  и собеседник не стал другим человеком — эти слои остаются.
- Смена задачи в панели меняет рабочий слой, долговременный остаётся,
  краткосрочный тоже: разговор-то тот же.

### В интерфейсе

- `Ctrl+M` — три слоя на месте панели параметров: что лежит, в каком слое
  и кто положил (`вручную` / `агент`). `Del` убирает запись.
- В шапке — сводка `🧠 chat 2 · task 5 · user 3`.
- `Ctrl+D` показывает слои отдельно от истории и помечает, какой уходит
  в промпт, а какой отключён полем «слои в промпт».
- Панель (`Ctrl+P`): «память» (выкл / руками / агентом), «юзер», «задача»
  и «слои в промпт».
- Служебный вызов раскладки виден в ленте, как сжатие дня 9 и факты дня 10,
  и считается в колонке «служеб» в `Ctrl+T`.

### Снаружи приложения

Рабочий слой курс разрешал держать хоть в трекере и забирать по API. У нас он
в файлах — значит, должен и читаться, и правиться снаружи:

```bash
go run ./cmd/advent memory                                  # что вообще есть
go run ./cmd/advent memory -user олег                       # долговременный слой
go run ./cmd/advent memory -task "бот барбершопа"           # рабочий слой
go run ./cmd/advent memory -user олег -put "стек = Go"
go run ./cmd/advent memory -task "бот барбершопа" -forget срок
```

## Сравнение: `advent dialog` с обрывом разговора

```bash
go run ./cmd/advent dialog -scenario scenarios/day11-memory.yaml
```

В сценарии появились две команды: `newchat: почему` обрывает разговор и
начинает новый тем же агентом, `remember: user/ключ = значение` кладёт
запись руками. В отличие от команд веток дня 10 их выполняют **все** варианты:
обрыв разговора — событие, а не приём одного варианта, и вариант без памяти
должен пройти через него тоже (и потерять всё — в этом сравнение и состоит).

Сценарий — тот же сбор ТЗ на бота барбершопа, 13 реплик. Шесть первых
заказчик рассказывает про себя и про задачу, две проверки идут **внутри**
разговора (их проходят все — история цела), потом `newchat`, и три проверки
**после** обрыва: бюджет и срок, правила отмены, кто я такой. Последняя
реплика просит собрать ТЗ заново.

## Ключевые файлы

| файл | что там |
|---|---|
| `internal/memory/memory.go` | слои, записи, блоки для системного промпта |
| `internal/memory/store.go` | файловое хранилище: `users/`, `tasks/`; краткосрочный слой сюда не пишется |
| `internal/memory/router.go` | промпт раскладки, разбор плана, применение разницы |
| `internal/memory/memory_test.go` | замена ключа, порядок, раздельные файлы, мусор в ответе раскладки |
| `internal/agent/memory.go` | режимы памяти, служебный вызов раскладки, ручная запись |
| `internal/agent/memory_test.go` | слои в промпте, сброс, новый разговор, перезапуск, смена задачи |
| `internal/tui/memory.go` | `Ctrl+M`, команды `/user`, `/task`, `/chat`, `/forget` |
| `internal/tui/memory_test.go` | панель, команды из поля ввода, `Ctrl+R`, `Ctrl+D` |
| `internal/dialog/` | команды `newchat` и `remember`, слои в отчёте |
| `cmd/advent/day11.go` | `advent memory` — посмотреть и поправить слои снаружи |
| `scenarios/day11-memory.yaml` | сценарий сравнения |
| `tools/mockllm` | заглушка отвечает на раскладку планом и умеет читать блок памяти |
