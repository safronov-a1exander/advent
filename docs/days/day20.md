# День 20 — оркестрация MCP

Ветка: `day-20` (от `day-19`)

## Что добавляет этот шаг

Длинный флоу через несколько MCP-серверов. Ведущий курса развёл
девятнадцатый и двадцатый дни одной фразой: там — цепочка из tools scheme
одного сервера, здесь — «из нескольких MCP и нескольких tool scheme».

Серверов три, все свои, и у каждого своя область:

| сервер | транспорт | что знает | инструменты |
|---|---|---|---|
| `rates` «Курсы» | stdio | курсы ЦБ и рынка | `exchange_rate`, `convert`, слежение дня 18 |
| `budget` «Бюджет» | stdio | выписку по карте | `search_transactions`, `summarize_transactions`, `save_report` |
| `goals` «Цели» | stdio | цели накоплений — **только в рублях** | `add_goal`, `list_goals`, `plan_goal` |

Третий сервер — новый, и он нарочно узкий. Цель «60 000 лир к марту» он
принять не может: пересчёт — работа «Курсов», а сколько человек реально
откладывает — «Бюджета». Так устроены настоящие системы: банк не знает
курсов биржи, копилка не читает выписку. Ответ на вопрос «успею ли
накопить на поездку» не лежит ни в одном сервере — собрать его может
только агент.

## Маршрут строит агент

Одна реплика пользователя — шесть вызовов на трёх серверах:

```
«Хочу к 1 марта 2027 накопить на Стамбул — 60 000 лир. Сколько это в рублях?
 Сколько я откладываю? Заведи цель, посчитай, успеваю ли, сохрани план.»

  rates.convert              60000 TRY → RUB
  goals.add_goal             сумма в рублях — из результата convert
  budget.search_transactions переводы на накопительный счёт
  budget.summarize_transactions  сколько откладывается
  goals.plan_goal            цель + темп → успеваю / не успеваю
  budget.save_report         план — в файл
```

Порядок частично свободный, частично нет. Ветки «курс → цель» и
«выписка → сводка» друг от друга не зависят и могут идти как угодно.
Но цель нельзя завести до пересчёта (она в рублях), план нельзя
посчитать, пока нет и цели, и темпа, а отчёт — последним.

### Как устроена маршрутизация

Здесь почти всё уже было построено на семнадцатом дне, и двадцатый день
его проверяет:

- **имя функции — `сервер__инструмент`**: модель видит плоский список
  из всех серверов, а агент по имени находит сервер, которому
  адресован вызов;
- **соединение с сервером одно**, поднимается при первом обращении
  и общее для всех ходов;
- **выданные серверы — в конфиге агента**: функция чужого сервера,
  даже если модель её выдумала, не выполнится;
- **ошибка одного сервера — результат для модели**, а не сломанный флоу:
  «цели «Цель» нет: сначала add_goal» — и модель может исправиться.

## Проверяется маршрут, а не слова

В сценарии две новые проверки.

**`chains`** — несколько цепочек, каждая как `tools` дня 17: вызовы
по порядку, между ними могут быть другие. Так выражается «частично
свободный» порядок:

```yaml
chains:
  - [rates.convert, goals.add_goal, goals.plan_goal, budget.save_report]
  - [budget.search_transactions, budget.summarize_transactions, goals.plan_goal]
```

**`passes`** — стык двух серверов: число из **результата** одного
инструмента должно оказаться в **аргументах** другого.

```yaml
passes:
  - {from: rates.convert, to: goals.add_goal}
```

Это «корректность передачи» между серверами, которую не может проверить
ни один из них: «Цели» не знают, откуда пришла сумма, «Курсы» — куда
ушла. Видит оба вызова только агент — значит, и проверять стык нужно
там. Числа из вопроса не считаются: цель на 60 000 — это лиры из
вопроса, положенные в поле рублей, и проверка на это не поведётся.

## Сравнение: лишние серверы

Второй вариант сценария — те же три сервера плюс два чужих публичных
с шестнадцатого дня, `deepwiki` и `context7`. К финансам они отношения
не имеют. Вопросов два:

1. **Не собьётся ли агент с маршрута**, когда функций больше
   (17 вместо 12) и часть из них — про совсем другое.
2. **Сколько стоит лишняя схема.** Её платят в каждом круге каждого хода,
   даже если ни одна чужая функция не вызвана. Это та самая лекционная
   «эффективность 2%»: подключить всё подряд — значит платить за всё
   подряд.

## Сравнение: `advent dialog`, четыре реплики

1. длинный флоу через три сервера (шесть вызовов, две цепочки, стык);
2. «а если по 25 000 в месяц?» — короткий флоу, курс и выписка не нужны;
3. два независимых вопроса к двум серверам в одной реплике;
4. «спасибо» — инструменты не нужны.

## Проверено

Тестами сервера «Цели»: полные месяцы до срока, план «не успеваешь»
с нужной суммой в месяц и «успеваешь» с датой, цели переживают
перезапуск, ошибки — прошедший срок, нулевая сумма, дата не в формате;
тестами проверок: стык честный, стык «лиры вместо рублей», стык без
первого вызова.

На заглушке: 4/4 у обоих вариантов, длинный флоу — шесть вызовов на трёх
серверах в правильном порядке; с двумя чужими серверами вход на 57%
больше при тех же вызовах. На репетиции заглушка однажды позвала
`plan_goal` раньше `add_goal` — проверка цепочки это поймала,
а сервер «Целей» вернул ошибку результатом, и ход не сломался.
Выбирает маршрут заглушка по правилам, поэтому само умение модели
выбирать покажет только живой прогон.
