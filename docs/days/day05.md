# День 5 — Версии моделей

Ветка: `day-05` (от `day-04`)

## Что добавляет этот шаг

`scenarios/day05-models.yaml` — три конфигурации одного рабочего запроса
ассистента (разбор выписки и расчёт остатка бюджета):

| вариант | модель | режим |
|---|---|---|
| слабая | `deepseek-v4-flash` | `thinking: disabled` |
| средняя | `deepseek-v4-flash` | `thinking: enabled` |
| сильная | `deepseek-v4-pro` | `thinking: enabled` |

Средний вариант — это **та же модель**, что и слабый, только с включёнными
рассуждениями. Так видно, что разницу даёт не только размер модели, но и
режим инференса — а reasoning-токены при этом оплачиваются как output.

Добавилось в код:

- колонка **ТОК/С** — скорость генерации (`completion / latency`). Абсолютная
  задержка зависит ещё и от длины ответа, поэтому сравнивать модели по ней
  нечестно;
- секция **Модели** в markdown-отчёте: класс, число параметров, квантизация,
  контекст, прайс и ссылка на страницу модели — это и есть материал
  для вывода о выборе модели;
- в `config.yaml` у моделей появились поля `params_b`, `quant`, `url`;
- в панели — поле `класс`: переключает модель между `weak`/`medium`/`strong`
  из конфига, не заставляя помнить имена;
- **Ctrl+E в чате** отправляет последний заданный вопрос на все модели
  провайдера подряд и печатает таблицу «задержка / ток/с / токены / цена».
  То есть сравнение делается и вручную, без YAML-сценария; каждый вызов
  при этом попадает в `runs/*.jsonl`.

## Проверено на живом API

Замер на реальном ключе, два прогона на конфигурацию:

| конфигурация | задержка | ток/с | out | reasoning | $ | верно |
|---|---:|---:|---:|---:|---:|---|
| flash без рассуждений | 2.4 с | 101 | 488 | 0 | 0.00086 | 2/2 |
| flash с рассуждениями | 7.4 с | 155 | 2303 | 1936 | 0.00332 | 2/2 |
| pro с рассуждениями | 27.4 с | 71 | 3886 | 3642 | 0.01623 | 2/2 |

Вывод, который стоит произнести цифрами: **все три справились**, но самая
дешёвая конфигурация в 19 раз дешевле и в 11 раз быстрее старшей модели.
На разборе выписки `pro` не даёт ничего сверху — значит ассистенту он
в этой роли не нужен.

Ещё два наблюдения:

- **Reasoning-токенов больше, чем самого ответа.** У `pro` из 3886
  completion-токенов 3642 ушли в рассуждения. Их не видно в ответе, но
  платишь за них ты.
- **Скорость нельзя мерить задержкой.** У `flash` с рассуждениями задержка
  втрое больше, чем без них, а токенов в секунду — в полтора раза больше:
  модель просто пишет намного длиннее.

Проверено: `GET /models` отдаёт ровно
`deepseek-v4-flash`, `deepseek-v4-pro`, `deepseek-v4-flash-vision-exp`.

## На что смотреть при прогоне

1. **Сверить имена моделей.** Сценарий ссылается на `deepseek-v4-flash` и
   `deepseek-v4-pro` — сверь с тем, что доступно на твоём аккаунте:
   ```bash
   go run ./cmd/advent models
   ```
   Если реальные имена другие — поправить `config.yaml` и `scenarios/day05-models.yaml`.
2. **Прайс уже сверен** с https://api-docs.deepseek.com/quick_start/pricing:
   у DeepSeek две ставки, пиковая и вдвое дешевле в непиковые часы
   (пик — 01:00–04:00 и 06:00–10:00 UTC, пн–пт). В `config.yaml` стоят
   пиковые, чтобы колонка стоимости не занижала расход. Если прайс изменится —
   поправить там же.
3. `thinking: {"type": "disabled"}` проверен — принимается, HTTP 200,
   reasoning-токены в ответе обнуляются.
4. Прогнать:
   ```bash
   go run ./cmd/advent run -scenario scenarios/day05-models.yaml
   ```
5. Заполнить `params_b` и `quant`, если DeepSeek публикует эти цифры;
   если нет — оставить прочерк и сказать об этом в видео (закрытые веса —
   тоже факт о модели).
