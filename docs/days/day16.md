# День 16 — подключение к MCP

Ветка: `day-16` (от `day-15`)

## Что добавляет этот шаг

Клиент Model Context Protocol и команда `advent mcp`: соединиться
с сервером, пройти рукопожатие и получить список инструментов. Модели на
этом шаге ещё нет — ведущий курса так и сказал: «здесь пока с MCP работать
не нужно, просто запросить get tools у любого общедоступного MCP».

Подключены три публичных сервера без ключа — не ради количества, а потому
что они ведут себя по-разному, и клиент должен выдержать все три:

| сервер | что это | чем интересен |
|---|---|---|
| `deepwiki` | документация GitHub-репозиториев | отвечает потоком SSE; длинная инструкция модели в `initialize` |
| `context7` | документация библиотек | два инструмента, но самая тяжёлая схема: 4.5 КБ |
| `gitmcp` | документация любого проекта | выдаёт сессию и говорит на старой ревизии протокола |

## Что ходит по проводу

MCP — не фреймворк, а протокол: JSON-RPC 2.0 поверх одного из двух
транспортов. Удалённый сервер (Streamable HTTP) принимает POST на один
адрес, локальный запускается подпроцессом и говорит через stdin/stdout
(понадобится на семнадцатом дне, когда сервер будет свой).

`advent mcp -wire` печатает обмен как есть:

```
→ {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18",…}}
← {"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-03-26","capabilities":{"tools":{…}},…}}
→ {"jsonrpc":"2.0","method":"notifications/initialized"}
→ {"jsonrpc":"2.0","id":2,"method":"tools/list"}
← {"jsonrpc":"2.0","id":2,"result":{"tools":[…]}}
```

Три шага рукопожатия, и в каждом есть на чём споткнуться:

1. **`initialize`** — клиент называет свою ревизию протокола, сервер
   отвечает своей. Они могут не совпасть: `gitmcp` на просьбу `2025-06-18`
   ответил `2025-03-26`. Дальше клиент говорит на версии сервера и шлёт её
   заголовком `MCP-Protocol-Version` в каждом запросе.
2. **`notifications/initialized`** — уведомление без `id`, ответа на него
   нет (HTTP 202). До него сервер вправе не отвечать ни на что.
3. **`tools/list`** — список может прийти страницами: пока в ответе есть
   `nextCursor`, клиент спрашивает следующую.

### Два вида ответа

Клиент обязан принимать и `application/json`, и `text/event-stream` —
какой прислать, решает сервер. Все три публичных сервера ответили потоком.
В потоке до нужного ответа может прийти что угодно: уведомление о прогрессе,
встречный `ping` от сервера. Клиент пропускает всё, у чего не тот `id`,
а не хватает первое попавшееся сообщение.

### Сессия — это заголовок, а не соединение

Если сервер выдал `Mcp-Session-Id` в ответ на `initialize`, его нужно
слать дальше в каждом запросе, иначе сервер с сессиями ответит ошибкой.
Если сервер сессию забыл (перезапустился), он отвечает 404 — и клиент
говорит об этом прямо: «сессия больше не действует, нужно заново
initialize», а не голое `http 404`. На выходе сессия закрывается явным
`DELETE`.

## Почему без SDK

SDK для MCP есть почти на каждом языке, включая официальный для Go. Взять
его было бы быстрее — но это ровно та ситуация, что на первой неделе
с клиентом к LLM: за SDK не видно, что ходит по проводу. А по проводу
ходит немного, и весь клиент — около шестисот строк вместе с комментариями: протокол, транспорт
и рукопожатие. Ведущий курса предупреждал, откуда путаница: «у людей
возникает ощущение, что это конкретный фреймворк». Написанный руками
клиент эту путаницу снимает.

## Схема стоит токенов — это видно уже сейчас

Каждый инструмент — имя, описание и JSON Schema аргументов. Модели эта
схема уходит в каждом запросе, пока сервер подключён, — даже если за весь
разговор ни один инструмент не понадобился. Об этом половина лекции недели:
в её примере на два вызова инструмента 98% токенов ушло на обслуживание
MCP и только 2% — на то, что написал пользователь.

Поэтому `advent mcp` печатает размер схемы рядом со списком:

```
tools/list  205 мс · инструментов 2 · схема 4.5 КБ ≈ 1147 токенов
```

Оценка грубая — четыре байта на токен, схемы почти целиком латиница и
JSON. Точную цифру покажет usage провайдера, когда схема впервые уйдёт
модели (день 17). Но порядок виден уже здесь: у `context7` два инструмента
весят больше, чем пять у `gitmcp`, — одно описание `query-docs` длиннее
многих чужих схем целиком. Количество инструментов о стоимости сервера
почти ничего не говорит.

## Снаружи приложения

```bash
go run ./cmd/advent mcp                                  # все серверы из config.yaml
go run ./cmd/advent mcp -server gitmcp -wire             # один сервер и JSON-RPC на проводе
go run ./cmd/advent mcp -url https://mcp.deepwiki.com/mcp  # любой адрес без записи в конфиг
go run ./cmd/advent mcp -full                            # описания инструментов целиком
```

Серверы описаны в `config.yaml` в списке `mcp_servers`. Ключ, если он
нужен, в конфиг не пишется: в заголовке стоит `${ПЕРЕМЕННАЯ}`, и она
берётся из окружения или `.env`. Переменная не задана — заголовок
не уходит вовсе. `config.local.yaml` может заменить сервер целиком
или добавить свой.

## Проверено на живых серверах

| сервер | рукопожатие | протокол | сессия | инструментов | схема |
|---|---:|---|---|---:|---:|
| `deepwiki` | 1186 мс | 2025-06-18 | нет | 3 | 1.0 КБ ≈ 264 т. |
| `context7` | 1005 мс | 2025-06-18 | нет | 2 | 4.5 КБ ≈ 1147 т. |
| `gitmcp` | 1531 мс | 2025-03-26 | есть | 5 | 2.8 КБ ≈ 718 т. |

Вместе — десять инструментов и около двух тысяч токенов, которые ехали бы
в каждый запрос к модели, подключи мы все три сервера разом.

Ещё одна деталь из живого прогона: `deepwiki` в ответ на `initialize`
присылает инструкцию на три тысячи символов — со списком двадцати
инструментов, из которых доступны три (остальные «private mode only»).
Инструкция — тоже текст, который клиент может положить в промпт. Сервер
решает, что там написано, а платит за это клиент.

## Ключевые файлы

| файл | что там |
|---|---|
| `internal/mcp/protocol.go` | JSON-RPC 2.0, рукопожатие, описание инструмента и разбор его аргументов |
| `internal/mcp/client.go` | `Connect` (initialize → initialized), `ListTools` со страницами, трасса провода |
| `internal/mcp/http.go` | Streamable HTTP: JSON и SSE, сессия, версия протокола в заголовке, `DELETE` на выходе |
| `internal/mcp/spec.go` | описание сервера из `config.yaml`, заголовки из окружения |
| `internal/mcp/http_test.go` | рукопожатие, SSE с чужими сообщениями, сессия и её истечение, страницы, сервер без tools |
| `cmd/advent/day16.go` | команда `advent mcp` |
