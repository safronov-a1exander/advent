# День 30 — локальная модель как приватный сервис

Ветка: `day-30` (от `day-29`)

## Что добавляет этот шаг

llama-server слушает только `127.0.0.1`: он ничего не знает о том, кто
к нему пришёл, и открывать его в сеть как есть нельзя даже для домашних
устройств. Перед ним встаёт шлюз — `advent serve`:

```
телефон, ноутбук ──► advent serve :8095 ──► llama-server 127.0.0.1:8080 ──► RTX 4060
 (локальная сеть)     ключ · лимит · очередь       Qwen3-4B Q4_K_M,
                      окно · страница чата         2 слота по 4096
```

| что | как |
|---|---|
| доступ | `Authorization: Bearer <ключ>`; без ключа — 401. Ключ на устройство или человека, по нему видно в логе, чей запрос |
| лимит запросов | ведро токенов на ключ: 30 в минуту, подряд — `-burst`. Сверх — 429 и `Retry-After` |
| стабильность | в модели одновременно столько запросов, сколько слотов у llama-server (`-parallel` = `-np`), остальные ждут в очереди; очередь полна — 503 сразу, а не зависший запрос |
| окно | промпт считается токенизатором самой модели (`/tokenize`) вместе со схемами инструментов. Промпт + `max_tokens` не влезают в окно слота — 413 до генерации, а не обрезанный ответ через минуту |
| ответ | `max_tokens` больше потолка урезается; модель выбирает шлюз — поле `model` клиента не учитывается |
| API | тот же OpenAI-совместимый `/v1/chat/completions`, с потоком SSE: клиент стенда подключается сменой `base_url` |
| чат | страница на `/` — открывается с телефона по адресу в сети, ключ вводится на странице |
| наблюдение | строка лога на запрос (кто, код, время, размер промпта), `/health` без ключа, `/v1/stats` — ответы по кодам |

Почему шлюз, а не флаги самого llama-server: у него есть `--api-key`,
но один на всех, без лимитов на ключ и без проверки окна до генерации.

## Настройка модели — из дня 29

```powershell
.\scripts\local-llm.ps1 -Context 8192 -Parallel 2 -Extra @('-fa','on','-ctk','q8_0','-ctv','q8_0')
```

Окно 8192 на два слота — по 4096 на запрос: в день 29 выяснили, что
расчёту по выписке этого хватает, а KV-кэш q8_0 экономит видеопамять.
Два слота — два запроса считаются одновременно, каждый чуть медленнее,
но второй не ждёт первого целиком.

## Код

| файл | что там |
|---|---|
| `internal/gateway/gateway.go` | шлюз: ключи, ведро токенов, очередь, окно, прокси с потоком |
| `internal/gateway/chat.html` | страница чата, встроена в бинарь (`go:embed`) |
| `cmd/advent/day30.go` | `advent serve` и `advent load` |
| `config.yaml` | провайдер `private` — адрес шлюза |

**Ключи** — файл `keys.txt` в корне проекта, вне репозитория: строка
«имя ключ». Выдать ключ:

```powershell
.\advent.exe serve -new-key ноутбук
.\advent.exe serve -new-key телефон
```

**Адрес в сети** у каждой машины свой, поэтому в `config.yaml` у провайдера
`private` стоит `127.0.0.1`, а настоящий адрес и ключ — в `config.local.yaml`:

```yaml
providers:
  - name: private
    base_url: http://192.168.1.10:8095/v1
    api_key: sk-local-…
```

**Порт 8095, IPv4 явно.** На этой машине `0.0.0.0:8090` держит посторонний
процесс. Go, слушая `0.0.0.0`, садится на двойной стек `[::]`, и Windows
это разрешает. Сервис «запустился», но запросы на IPv4 уходили в чужую
программу и получали 501. Теперь IPv4-адрес слушается как `tcp4`:
занятый порт — ошибка при старте.

## Проверка: `advent load`

Клиент, который проверяет сервис так, как его видит другое устройство:
по адресу в сети, с ключами двух пользователей. Шлюз для записи запущен
с `-rate 30 -burst 12 -parallel 2 -queue 3`.

| проверка | что видно |
|---|---|
| 1. доступ по сети | `/health` без ключа — 200; `/v1/models` без ключа — 401, с ключом — 200; неверный ключ — 401 |
| 2. стабильность | 4 запроса одновременно от двух ключей — 4×200; ответы приходят парами (1.1 / 1.1 / 1.8 / 1.8 с): в модели два слота |
| 3. очередь | 9 запросов одновременно — 5×200 (2 в модели + 3 в очереди), 4×503 сразу |
| 4. окно | выписка, повторённая 12 раз: «промпт 4393 + ответ 256 > окна 4096» — 413 |
| 5. лимит | запросы подряд с одного ключа: шесть по 200, седьмой — 429 с `Retry-After 2`; тут же с другого ключа — 200 |

Лимит считается на ключ: всплеск с ноутбука не задевает телефон.

## Через сервис — обычный клиент

`advent chat -provider private` и `advent dialog -provider private` —
те же команды, что с DeepSeek и с локальной моделью. Сценарий дня 27
(три MCP-инструмента подряд) через шлюз проходит целиком: каждый шаг
цепочки — отдельный запрос к сервису, и промпт с схемами инструментов
(500–1200 токенов) проверяется на окно до генерации. `-offline` считает
адрес `192.168.x.x` своей сетью: облака по-прежнему нет.

## Сеть и брандмауэр

Сервис слушает все интерфейсы (`0.0.0.0:8095`), `advent serve` при старте
печатает адреса, по которым его видно. Чтобы до него достучался телефон,
брандмауэр Windows должен пропускать входящие к `advent.exe`. При первом
запуске Windows спрашивает об этом сам. На этой машине сеть помечена как
общедоступная (Public), и для `advent.exe` уже стояло правило Block —
его нужно заменить разрешающим, только для частной сети и порта сервиса.

Наружу, в интернет, сервис не выставлен. Для доступа извне нужен
проброс порта или туннель, а с ними — TLS: ключ идёт в заголовке открытым
текстом. В локальной сети это допустимо, в интернете — нет.

## Запись демо

Перед записью: модель с двумя слотами и шлюз в отдельном окне.

```powershell
$env:LLAMA_CPP_DIR = 'C:\Users\sanya\tools\llama'   # если не $HOME\tools\llama
.\scripts\rag-servers.ps1 -Stop
.\scripts\local-llm.ps1 -Context 8192 -Parallel 2 -Extra @('-fa','on','-ctk','q8_0','-ctv','q8_0')
go build -o advent.exe ./cmd/advent
Start-Process powershell -ArgumentList '-NoExit','-Command','.\advent.exe serve -rate 30 -burst 12 -parallel 2 -queue 3'

$k2 = ((Get-Content keys.txt -Encoding UTF8 | Where-Object { $_ -like 'телефон *' }) -split ' ')[1]
Remove-Item -Recurse -Force runs\sessions-day30 -ErrorAction SilentlyContinue
$t = 'advent · день 30 — приватный сервис'
.\scripts\demo.ps1 -Name day30 -MaxSeconds 1200 -AppArgsList @(
  @('load','-key2',$k2,'-hold','30s'),
  @('demo','-script','scripts/day30.demo','-provider','private','-offline','-mcp','budget','-thinking','disabled','-sessions','runs/sessions-day30','-new','-title',$t))
```

Шлюз между частями не перезапускать: в части 1 лимит ключа «ноутбук»
выбран до 429, и через секунды он восстанавливается сам (30 в минуту).

Телефон в эту запись не попадает: `demo.ps1` пишет одно окно. Его снять
отдельно: открыть `http://<адрес>:8095/` в браузере телефона, ввести ключ
«телефон», задать вопрос — в окне шлюза появится строка с именем `телефон`.
