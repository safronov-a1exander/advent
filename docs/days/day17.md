# День 17 — первый инструмент MCP

Ветка: `day-17` (от `day-16`)

## Что добавляет этот шаг

Свой MCP-сервер и первый вызов инструмента агентом. Три части:

1. **Сервер «Курсы»** (`advent mcp-server rates`) вокруг API курсов ЦБ РФ:
   два инструмента, `exchange_rate` и `convert`, со схемой аргументов.
2. **Вызов функций в клиенте к LLM**: схема уходит в запросе полем `tools`,
   модель отвечает не текстом, а `tool_calls`.
3. **Цикл хода в агенте**: модель попросила инструмент → агент вызвал его
   через MCP → результат вернулся модели сообщением `tool` → модель
   ответила. Повторяется, пока модель не ответит текстом.

Почему курсы. Задание — сервер «вокруг любого API». Для ассистента по
личным тратам это самый нужный внешний API: в выписке есть списание
в долларах, в поездке траты в лирах, а курса модель не знает и знать
не может — у неё дата обучения, а курс меняется каждый день. Без
инструмента она обязана либо отказаться, либо назвать курс по памяти.

## Сервер: маппинг инструмента на HTTP-запрос

Главный слайд лекции — ровно это место: инструмент, который видит модель,
превращается в конкретный запрос к сервису, а ответ сервиса —
в `CallToolResult`.

| инструмент | аргументы | запрос к ЦБ |
|---|---|---|
| `exchange_rate` | `currency*`, `date` | `GET /daily_json.js` или `/archive/ГГГГ/ММ/ДД/daily_json.js` |
| `convert` | `amount*`, `from*`, `to` (RUB), `date` | тот же запрос, кросс-курс через рубль с учётом номинала |

Что пришлось решить по дороге — и всё это то, чего модель не знает:

- **Номинал.** ЦБ публикует курс лиры за 10 единиц, драма — за 100.
  «1 TRY = 17 RUB» из сырой таблицы — ошибка в десять раз.
- **Выходные.** ЦБ не публикует курс в субботу и воскресенье. Курс на
  выходной — курс последнего рабочего дня перед ним, и сервер сам шагает
  назад, а в ответе называет дату, по которой считал.
- **Ошибка инструмента — это результат, а не сбой.** «Валюты XXX нет»,
  «дата в будущем», «дата не в формате ГГГГ-ММ-ДД» приходят модели обычным
  результатом с `isError: true`: она может поправить аргумент и спросить
  снова. Сбоем протокола (`RPCError`) остаётся только то, что модель
  исправить не может, — неизвестный инструмент.
- **Два вида ответа.** Текст для модели («10 USD = 843.41 RUB по курсу ЦБ
  на 26.09.2026») и `structuredContent` для кода — тот же результат числами.
- **Аннотация `readOnlyHint`.** Инструменты только читают. Клиент
  проверить это не может, спецификация прямо просит аннотациям не
  доверять, — но честный сервер их заявляет.

Источник — JSON-зеркало `cbr-xml-daily.ru`: те же цифры, что у `cbr.ru`,
но в UTF-8 и с архивом по датам (сам `cbr.ru` отдаёт XML в windows-1251).
Прошедший день кэшируется навсегда, последний курс — на десять минут.

### Транспорт stdio

Свой сервер локальный, поэтому транспорт — stdio: клиент запускает его
подпроцессом и говорит построчным JSON через stdin/stdout. Отсюда правило,
которое легко нарушить: **stdout сервера занят протоколом**, любая строка
журнала туда ломает клиенту разбор. Журнал — только в stderr
(`advent mcp-server rates -log`), а клиент держит хвост stderr и
показывает его, если сервер упал.

Ответы по stdio приходят в том порядке, в каком сервер их закончил, а не
в каком ушли вопросы. Поэтому ответы читает одна горутина и раздаёт
ждущим по `id`, а сервер обрабатывает каждый вызов в своей горутине —
медленный инструмент не держит соседние.

Сервер живёт в том же бинаре, что и клиент. В `config.yaml` он описан
командой `"@self"` — это сам `advent`, путь к нему прописывать не нужно:

```yaml
mcp_servers:
  - name: rates
    command: "@self"
    args: [mcp-server, rates]
```

## Агент: цикл хода с инструментами

```
вопрос ─► модель (+ схема функций)
            │ tool_calls: rates__convert {"amount":10,"from":"USD"}
            ▼
          агент ─► MCP tools/call ─► сервер ─► ЦБ
            │ tool: "10 USD = 843.41 RUB …"
            ▼
          модель (+ та же схема, + вызов, + результат) ─► ответ
```

- **Имя функции — `сервер__инструмент`.** Модель видит плоский список
  функций, а агенту нужно вернуться от имени к серверу. Так же устроены
  готовые ассистенты, и так у двух серверов могут быть инструменты
  с одинаковыми именами (понадобится на двадцатом дне).
- **Выдаёт серверы конфиг агента** (`mcp: [rates]`), а соединение одно на
  процесс (`mcp.Hub`). И имя функции проверяется по выданным серверам:
  его пишет модель, и выдуманное `bank__transfer` не должно открыть
  сервер, который агенту не выдан.
- **Любая беда вызова — результат для модели.** Неизвестная функция,
  битый JSON аргументов, упавший сервер: модель получает «ОШИБКА: …»
  и решает, что делать. Ход не ломается.
- **Лимит кругов.** Восемь кругов вызовов на ход; на последнем функции
  у модели забираются, и она обязана ответить. Иначе зациклившаяся модель
  тратила бы деньги бесконечно.
- **В историю — вопрос и ответ, а не сырые результаты.** Вызовы видны
  в ленте, в журнале и в отчёте, но следующий ход их не тащит: иначе
  один запрос выписки раздувал бы каждый последующий вопрос.
- **Без стриминга.** Пока модель не ответила, непонятно, текст это или
  вызов; текст рядом с вызовами («сейчас посмотрю») — не ответ. Ответ
  с инструментами приходит целиком.

### Схема оплачивается в каждом круге

Каждый круг — отдельный вызов API, и схема функций в нём оплачивается
заново: вопрос с одним вызовом инструмента — это два запроса к модели,
и во втором уже есть и вопрос, и вызов, и результат. Поэтому в строке
токенов после ответа — сколько функций ушло в схеме и сколько вызвано,
а в учёте хода — `ToolCalls` и `ToolRounds`.

## Проверки: поведение, а не слова

Курс меняется каждый день, поэтому проверить ответ подстрокой нельзя.
Сценарий проверяет поведение — три новые проверки реплики:

| проверка | что значит |
|---|---|
| `tools: [rates.convert]` | инструменты вызваны в этом порядке (между ними могут быть другие); вызов с ошибкой не засчитывается |
| `uses_result: true` | в ответе есть число из результата инструмента, которого не было в вопросе. «Получите и используйте результат» — ровно это: вызвать и ответить своими словами — не одно и то же |
| `no_tools: true` | инструмент звать незачем. Лишний вызов — деньги и задержка; модель, которая зовёт курс на «привет», неправа так же, как модель, которая курс придумывает |

## Снаружи приложения

```bash
go run ./cmd/advent mcp -server rates                     # свой сервер — как любой другой
go run ./cmd/advent mcp -server rates -wire -call convert -args '{"amount":10,"from":"USD"}'
go run ./cmd/advent chat -mcp rates                       # агент сам решает, когда звать инструмент
go run ./cmd/advent dialog -scenario scenarios/day17-first-tool.yaml
```

## Сравнение: `advent dialog`, шесть реплик

Два варианта: без инструментов и с MCP «Курсы». Реплики: приветствие
(инструмент не нужен), 10 долларов Spotify в рубли, курс евро на дату,
30 000 рублей в лиры, курс на несуществующее 31 сентября и «спасибо».

Первая реплика у обоих вариантов одинаковая, и инструмент на ней не
вызывается, — поэтому разница во входе на ней и есть цена схемы.

## Проверено

На заглушке (`-provider mock`) — с настоящим сервером-подпроцессом
и настоящим API ЦБ: вариант с MCP 5/5, без инструментов 2/5. Заглушка
проверяет весь путь — схема ушла, вызов пришёл, сервер ответил, результат
вернулся модели, — но не умение модели выбрать инструмент: его видно
только на живом API.

## Ключевые файлы

| файл | что там |
|---|---|
| `internal/servers/rates/` | сервер «Курсы»: источник ЦБ с кэшем и выходными, инструменты, тесты через трубы stdio |
| `internal/mcp/server.go` | MCP-сервер: регистрация инструментов, разбор JSON-RPC, `ServeStdio`, схема по порядку аргументов |
| `internal/mcp/stdio.go` | клиентский stdio: подпроцесс, раздача ответов по id, встречный ping, хвост stderr |
| `internal/mcp/hub.go` | серверы агента: ленивое подключение, имена `сервер__инструмент`, вызовы с ошибками для модели |
| `internal/llm/` | `tools` в запросе, `tool_calls` в ответе — целиком и кусками из потока |
| `internal/agent/tools.go` | цикл хода с инструментами, лимит кругов, учёт |
| `internal/dialog/` | проверки `tools`, `uses_result`, `no_tools`; вызовы в отчёте |
| `tools/mockllm/tools.go` | вызовы функций на заглушке по правилам |
| `scenarios/day17-first-tool.yaml`, `scripts/day17.demo` | сравнение и демо |
