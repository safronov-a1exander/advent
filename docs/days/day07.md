# День 7 — Разговор переживает перезапуск

Ветка: `day-07` (от `day-06`)

## Что добавляет этот шаг

Агент шестого дня жил в памяти процесса: закрыл приложение — разговор
пропал. Теперь у пула агентов есть **хранилище сессий**: каждый разговор
пишется в `sessions/<id>.json` после каждого изменения, а при запуске пул
поднимает все сохранённые разговоры обратно. Для пользователя это как
в любом чат-клиенте: закрыл, открыл — разговоры на месте, открыт последний,
и он продолжается с того же места, потому что модели уходит та же история,
что и до перезапуска.

```bash
go run ./cmd/advent chat                     # открывает последний разговор
go run ./cmd/advent chat -new                # новый; старые остаются в Ctrl+O
go run ./cmd/advent chat -session бюджет-003 # конкретный
go run ./cmd/advent chat -no-save            # только в памяти, как на шестом дне
go run ./cmd/advent sessions                 # что сохранено
go run ./cmd/advent sessions -show бюджет-003
```

Каталог задаётся `sessions_dir` в `config.yaml` или флагом `-sessions`.

### Почему JSON, а не SQLite

Задание разрешает оба. Выбран JSON, по файлу на разговор: его можно открыть
глазами, поправить руками, приложить к отчёту или положить в тест. На одного
пользователя с десятками разговоров база не даёт ничего, кроме лишней
зависимости — драйвера. Если разговоров станут тысячи или понадобится поиск по ним —
`agent.Store` это интерфейс, и замена хранилища не трогает ни агента, ни экран.

### Что сохраняется

```json
{
  "version": 1,
  "id": "бюджет-001",
  "provider": "deepseek",
  "created": "...", "updated": "...", "rev": 5,
  "config":  { "model": "deepseek-flash", "system": "...", "temperature": 0.3 },
  "history": [ { "role": "user", "content": "..." }, { "role": "assistant", "content": "..." } ],
  "stats":   { "turns": 2, "calls": 2, "prompt_tokens": 213, "completion_tokens": 57, "cost_usd": 0.00003 }
}
```

Конфиг сохраняется вместе с историей: после перезапуска разговор продолжается
с той же моделью и тем же системным промптом, что были, а не с флагами
текущего запуска.

### Решения, которые стоит знать

- **Когда пишется.** После каждого успешного ответа, сброса контекста
  и смены настроек. Неотвеченный вопрос в историю не попадает (день 6),
  поэтому и на диск тоже.
- **Атомарно.** Сначала `<id>.json.tmp`, потом переименование. Упадёт процесс
  посреди записи — на диске останется прежняя версия, а не обрезанный JSON.
- **Запоздавший снимок не затирает новый.** Сохранения идут из разных
  горутин: ответ агента и правка настроек в интерфейсе. У снимка есть
  ревизия, хранилище пропускает старую, если она пришла позже новой.
- **Пустой разговор не сохраняется.** Файл появляется с первой репликой —
  иначе каждый запуск с `-new` оставлял бы в списке пустышку. Однажды
  сохранённый разговор пишется всегда, в том числе пустым после сброса.
- **Тот же конфиг — не повод для записи.** Экран отдаёт конфиг агенту перед
  каждым вопросом; без сравнения каждый вопрос означал бы лишнюю запись.
- **Закрыть не значит уничтожить.** `Ctrl+W` в списке агентов переносит файл
  в `sessions/archive/<id>-<время>.json`.
- **Временные агенты не пишутся.** Агенты сравнения моделей по `Ctrl+E`
  создаются через `SpawnTemp` — иначе каждый прогон оставлял бы мусор.
- **Разговор принадлежит провайдеру.** Модели у провайдеров называются
  по-разному, и разговор, начатый на DeepSeek, на заглушке не продолжить.
  Пул поднимает только разговоры своего провайдера, остальные не трогает.
- **Нумерация продолжается.** После восстановления новый агент получает id
  после самого старшего — чужой файл не перезапишется.
- **Битый файл не мешает остальным.** Он перечисляется в предупреждении
  в начале ленты, остальные разговоры поднимаются.
- **Ошибка записи видна.** Если сохранить не удалось, после ответа в ленте
  появляется строка с ошибкой: молча потерянный разговор хуже любой ошибки.

### В интерфейсе

- При запуске открывается последний по времени разговор, и **лента
  восстанавливается из истории** с пометкой, из какого файла и сколько в нём
  сообщений.
- В списке агентов (`Ctrl+O`) у каждого разговора время последнего изменения.

## Ключевые файлы

| файл | что там |
|---|---|
| `internal/agent/session.go` | `Snapshot`, интерфейс `Store`, `FileStore` |
| `internal/agent/pool.go` | `SetStore`, `Restore`, `SpawnTemp`, сохранение по изменению |
| `internal/agent/agent.go` | ревизия, время изменения, уведомление пула |
| `internal/agent/session_test.go` | перезапуск и продолжение, атомарность, архив, провайдеры, битые файлы |
| `internal/tui/chat.go` | выбор разговора при старте, восстановление ленты |
| `cmd/advent/day07.go` | флаги сессий, команда `sessions` |

## На что смотреть при прогоне

```bash
go test ./internal/agent/ -run 'Restart|Archive|Provider|Broken'
go run ./cmd/advent chat -new
# представиться, назвать бюджет, выйти по Ctrl+C
go run ./cmd/advent sessions
go run ./cmd/advent chat
# спросить «как меня зовут и какой у меня бюджет»
```

## Запись демо

Три запуска подряд в одном видео. Каталог сессий отдельный и перед записью
очищается, иначе в кадр попадут разговоры с репетиций:

```powershell
Remove-Item -Recurse -Force runs\sessions-day07 -ErrorAction SilentlyContinue
$t = 'advent · день 7 — разговор переживает перезапуск'
.\scripts\demo.ps1 -Name day07 -MaxSeconds 900 -AppArgsList @(
  @('demo','-script','scripts/day07-before.demo','-sessions','runs/sessions-day07','-new','-title',$t),
  @('sessions','-sessions','runs/sessions-day07','-show','бюджет-001','-hold','14s'),
  @('demo','-script','scripts/day07-after.demo','-sessions','runs/sessions-day07','-title',$t))
```
