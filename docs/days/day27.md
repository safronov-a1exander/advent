# День 27 — приложение на локальной модели

Ветка: `day-27` (от `day-26`)

## Что добавляет этот шаг

Приложение — тот же ассистент «Бюджет», что все предыдущие недели:
чат с сохранением разговоров (дни 6–7), инструменты MCP-сервера
выписки (дни 17–19). Новое — он работает целиком без облака,
и это проверяется кодом, а не на слово.

**`-offline`** (`cmd/advent/day27.go`). До старта чата проверяется
каждый адрес, куда он может пойти:

| звено | откуда адрес |
|---|---|
| модель | `base_url` провайдера |
| MCP по адресу | `url` сервера |
| MCP подпроцессом | считается своим — процесс на этой машине |
| эмбеддинги и реранкер | если включена база знаний |

«Своя сеть» — loopback и частные диапазоны (`10/8`, `172.16/12`,
`192.168/16`): домашний сервер в локальной сети тоже свой. Всё
остальное — облако, и чат не стартует:

```
$ advent chat -provider deepseek -offline
ошибка: -offline: в облако ведут модель → https://api.deepseek.com/v1
```

С локальной моделью в начале ленты — где что работает:
`офлайн: модель 127.0.0.1:8080 · mcp budget (процесс)`.

Оговорка про подпроцессы: снаружи не видно, ходит ли процесс в сеть
сам. `budget` и `goals` читают файлы, а `rates` берёт курсы с cbr.ru —
с `-offline` его подключать бессмысленно, хотя проверка его пропустит.

## Проверка: цепочка инструментов на 4B-модели

`scenarios/day27-local-app.yaml` — разговор дня 19 на Qwen3-4B
(Q4_K_M, `thinking: disabled`, `temperature: 0`):

| реплика | вызовы | проверки |
|---|---|---|
| траты на кафе за сентябрь + отчёт | search → summarize → save_report | ✓ 1390, сверка без расхождений |
| то же по покупкам | search → summarize → save_report | ✗ — см. ниже |

Вход 7,8 тыс. токенов (6 тыс. из кэша llama.cpp), выход ~520, $0.

**Второй ход падает, и падает стабильно.** Модель зовёт поиск
с `query: "покупки"` вдобавок к `category: "покупки"`. Строки «покупки»
в описаниях операций нет — выборка пустая, сводка честно даёт 0 ₽, отчёт
на 0 ₽ сохраняется. Проверка кодом (`expect: 2350`) это ловит. При
`temperature: 0` ошибка повторяется три прогона из трёх.

Тот же сценарий на той же модели, но с другими настройками сервера
(два слота, KV-кэш q8_0 — день 30) проходит 2/2. `temperature: 0` даёт
один и тот же ответ только при одной и той же конфигурации сервера:
квантовка кэша меняет числа в вычислениях, а с ними и выбор аргументов.
В живом чате (часть 1 видео) тот же вопрос идёт после первого хода
с другой историей — и там модель отвечает 2350.

Что видно:

- **Инструменты работают и на маленькой модели.** Шаблон чата Qwen3
  (`--jinja`) понимает `tools` в формате OpenAI, и цепочку из трёх
  вызовов модель собирает так же, как облачная: результат поиска
  (`dataset_id`) — аргумент сводки, итог сводки — в отчёт.
- **Арифметику по-прежнему делает сервер.** В день 26 та же модель без
  инструментов ошибалась в расчёте по выписке. Здесь считать ей не
  нужно — сумма приходит из `summarize_transactions`. Для маленькой
  модели это не украшение, а условие правильного ответа.
- **Кэш llama.cpp — как у DeepSeek.** Повторяющийся префикс (системный
  промпт, схемы инструментов, история) сервер не пересчитывает:
  три четверти входа — из кэша.

## Запись демо

```powershell

$t = 'advent · день 27 — «Бюджет» без облака'
.\scripts\demo.ps1 -Name day27 -MaxSeconds 1500 -AppArgsList @(
  @('demo','-script','scripts/day27.demo','-provider','local','-offline','-mcp','budget','-thinking','disabled','-sessions','runs/sessions-day27','-new','-title',$t),
  @('dialog','-provider','local','-scenario','scenarios/day27-local-app.yaml','-hold','30s'))
```
