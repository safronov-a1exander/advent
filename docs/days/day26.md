# День 26 — локальная модель

Ветка: `day-26` (от `day-25`)

## Что добавляет этот шаг

Клиент стенда с первого дня написан под OpenAI-совместимый
`/chat/completions`, а не под DeepSeek. Поэтому локальная модель — это
не новый код, а новый адрес: провайдер `local` в `config.yaml` смотрит
на `http://127.0.0.1:8080/v1`, и все команды стенда (`ask`, `chat`, `lab`,
`dialog`, …) работают с ней через `-provider local`.

| что | чем |
|---|---|
| движок | llama.cpp b11382, сборка с CUDA 12 — тот же, что держит эмбеддинги и реранкер базы знаний |
| модель | Qwen3-4B, квантовка Q4_K_M, 2.5 ГБ (`Qwen/Qwen3-4B-GGUF`) |
| железо | RTX 4060, 8 ГБ видеопамяти — все слои на GPU (`-ngl 99`) |
| API | `llama-server`: `/v1/chat/completions`, `/v1/models`, `/health`, `/metrics` |
| запуск | `scripts/local-llm.ps1` |

Почему llama.cpp, а не Ollama: он уже стоял и уже работал в RAG-неделе,
а Ollama под капотом — тот же llama.cpp плюс свой каталог моделей.
Почему Qwen3-4B: из моделей, что влезают в 8 ГБ вместе с bge-m3
и реранкером, она лучше всех держит русский, а режим рассуждений
у неё переключается на лету.

## Код

**`scripts/local-llm.ps1`** — поднимает `llama-server` в фоне, ждёт
`/health`, пишет лог в `chat.log`. Ключевые флаги:

- `--jinja` — шаблон чата берётся из самой модели. Без него не работают
  инструменты и переключатель рассуждений;
- `--alias qwen3-4b` — имя модели в API: по нему стенд находит в конфиге
  окно и цену (ноль);
- `-c 8192` — окно контекста. Это настройка сервера, а не предел модели
  (у Qwen3-4B — 32 тыс.): больше окно — больше видеопамяти под KV-кэш;
- `-Restart` — перезапуск с другой моделью или окном; останавливается
  только процесс на своём порту — эмбеддинги и реранкер не трогаются.

**Переключатель рассуждений.** У DeepSeek режим выключается полем
`thinking: {type: disabled}`. llama.cpp это поле игнорирует: у Qwen3
рассуждения включает шаблон чата, переменной `enable_thinking`.
У провайдера появилось поле `thinking_via: chat_template_kwargs` —
и тот же `-thinking disabled` (и поле в панели) уходит в запрос как
`chat_template_kwargs: {enable_thinking: false}`. Остальной код
о разнице не знает (`internal/llm/openai_compat.go`).

## Три запроса разной сложности

Через HTTP API напрямую:

```bash
curl http://127.0.0.1:8080/v1/chat/completions -H "Content-Type: application/json" \
  -d '{"model":"qwen3-4b","messages":[{"role":"user","content":"Сколько будет 17*23?"}]}'
```

Через CLI стенда:

```bash
go run ./cmd/advent ask -provider local "Сколько будет 15% от 60000 рублей?"
```

Через llama.cpp без стенда — `llama-cli -m Qwen3-4B-Q4_K_M.gguf -ngl 99`.

В демо — тот же чат, что в первый день, три вопроса:

1. **простой** — 15% от 60000;
2. **средний** — разложить пять трат по категориям в JSON-массив
   с полями `merchant`, `amount`, `category` (день 2);
3. **сложный** — выписка с четырьмя ловушками из дня 5: чужой месяц,
   перевод на копилку, снятие наличных, сумма в долларах. Верный
   ответ — 38865.

Первый замер на третьем вопросе (рассуждения включены):

| | |
|---|---|
| время | 62 с |
| выход | 4495 токенов, почти всё — рассуждения |
| скорость | ~75 ток/с |
| ответ | 41875 — неверно |

Длинное рассуждение не спасло: модель теряет условие посреди счёта.
Простое и среднее — без проблем. Сравнение с облаком на одних и тех же
вопросах — день 28, что с этим делать — день 29.

## Наблюдения

- **Ноль в колонке цены — не бесплатно.** Платим видеопамятью и временем:
  пока модель думает над выпиской, видеокарта занята целиком.
- **Reasoning-токены llama.cpp не отделяет.** В `usage` нет
  `completion_tokens_details`, поэтому в метрике `reasoning 0`, хотя
  текст рассуждений приходит отдельно (`reasoning_content`) и лежит
  в журнале. Все 4495 токенов посчитаны как обычный выход.
- **Первый токен — почти сразу.** Модель уже в видеопамяти, сети нет:
  на коротком вопросе llama.cpp разбирает промпт за ~35 мс (`timings`
  в ответе сервера).

## Ключевые файлы

| файл | что там |
|---|---|
| `scripts/local-llm.ps1` | запуск llama-server с чат-моделью |
