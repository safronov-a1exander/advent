# Архитектура: как устроен проект и где что лежит

Карта для тех, кто открыл репозиторий впервые. Дерево каталогов есть
в README, здесь то же самое словами: за что отвечает каждый каталог
и в какой последовательности до него доходит запрос.

## Путь одного запроса

Пользователь пишет в терминальном чате (`internal/tui`). Чат не ходит
в API сам: он отдаёт реплику агенту (`internal/agent`). Агент собирает
запрос: системный промпт, профиль пользователя, состояние задачи,
инварианты, слои памяти, найденные фрагменты базы знаний (`internal/rag`)
и схемы инструментов MCP-серверов (`internal/mcp`). Потом отправляет
его в модель через клиент OpenAI-совместимого API (`internal/llm`).
Каждый вызов пишется в журнал `runs/*.jsonl` (`internal/store`).
Провайдера, модель и цены задаёт `config.yaml` (`internal/config`).

## Точка входа — каталог cmd/advent

Один бинарь `advent` с подкомандами. Файл `main.go` разбирает команду
и печатает список всех команд. Остальные файлы называются по дню, в который
появилась команда: `day01.go` — ask, chat, demo; `day21.go` — index и search;
`day30.go` — serve и load; `day31.go` — dev, ассистент разработчика.

## Ядро — каталог internal

- **internal/llm** — провайдеро-независимый клиент `/chat/completions`:
  потоковый ответ (SSE), вызовы функций, учёт токенов и стоимости.
- **internal/config** — `config.yaml` плюс `config.local.yaml` и
  переменные окружения: провайдеры, модели с ценами, MCP-серверы,
  модели эмбеддингов, реранкеры, базы знаний.
- **internal/agent** — агент: история, стратегии контекста (окно, факты,
  сводка), память, профиль, задача, инварианты, цикл вызова инструментов,
  поиск по базе знаний и проверка цитат. Пул агентов живёт здесь же.
- **internal/tui** — интерфейс на bubbletea: чат, панель параметров,
  лаборатория сравнения вариантов, проигрыватель демо-сценариев.
- **internal/mcp** — Model Context Protocol: клиент, сервер, хаб, который
  держит соединения со всеми серверами, транспорты stdio и HTTP.
- **internal/servers** — свои MCP-серверы стенда: `rates` (курсы ЦБ и
  слежение по расписанию), `budget` (выписка: поиск, сводка, отчёт),
  `goals` (цели накоплений), `gitrepo` (git-репозиторий проекта).
- **internal/rag** — база знаний: загрузка документов, нарезка (окном
  или по разделам), эмбеддинги, индекс, поиск, реранк.
- **internal/memory**, **internal/profile**, **internal/task**,
  **internal/invariant** — слои памяти, профили пользователей, состояние
  задачи как конечный автомат, правила, которые нельзя нарушать.
- **internal/scenario**, **internal/runner**, **internal/report**,
  **internal/metrics**, **internal/dialog** — эксперименты: сценарий
  в YAML, прогон вариантов, markdown-отчёт, сходство ответов, один диалог
  в нескольких стратегиях контекста.
- **internal/gateway** — приватный сервис перед локальной моделью:
  ключи, лимит запросов, очередь, проверка окна, страница чата.
- **internal/store** — журнал вызовов в JSONL.

## Данные и конфиги в репозитории

- **config.yaml** — всё, что настраивается без кода. Секреты сюда не кладут:
  ключи — в `.env` или `config.local.yaml`, оба в `.gitignore`.
- **scenarios/** — YAML-сценарии экспериментов для `advent run` и `advent lab`.
- **profiles/**, **invariants/** — профили пользователей и наборы правил
  в markdown: это конфиг проекта, а не данные пользователя.
- **agents/fleet.yaml** — флот агентов для `advent swarm`.
- **data/statement.txt** — банковская выписка, данные продукта «Бюджет».
- **scripts/** — сборка, запуск локальных моделей (`local-llm.ps1`,
  `rag-servers.ps1`), демо-сценарии `dayNN.demo`, запись видео (`demo.ps1`).
- **tools/mockllm** — заглушка OpenAI-совместимого API для репетиций без
  трат на токены.
- **docs/** — `RUNBOOK.md` (порядок записи демо), `ARCHITECTURE.md`
  (этот файл), `days/dayNN.md` (что добавил каждый шаг и что замерено).

## Что создаётся при работе и в git не попадает

`runs/` — журналы вызовов, `reports/` — отчёты, `sessions/` — сохранённые
разговоры, `memory/` и `tasks/` — слои памяти и состояния задач, `index/` —
индексы базы знаний (собираются заново командой `advent index`),
`recordings/` — видео.

## Ветки

Один шаг — одна ветка `day-NN`, и каждая ответвляется от предыдущей.
Код шага N содержит весь код шагов до него. `main` — только инфраструктура.
Что именно добавил шаг, видно по `git diff day-(N-1)...day-N`.
